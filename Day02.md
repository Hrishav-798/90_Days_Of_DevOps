## 1. 🐧 What is Linux & What Does the Kernel Do?

When people say "Linux", they usually mean a complete operating system like Ubuntu, Debian, or Fedora. But technically, **Linux is just the kernel**.

### What is the Kernel?
The kernel is the core brain of the operating system. It sits directly between the hardware and the software applications:

```
  +-------------------------------------------------------+
  |              Applications / User Space                |
  |             (bash, git, curl, editors)                |
  +-------------------------------------------------------+
                             |
                   System Calls (syscalls)
                             |
  +-------------------------------------------------------+
  |                     LINUX KERNEL                      |
  |  - Process Management   - Memory Management           |
  |  - File System Driver   - Hardware Device Drivers     |
  +-------------------------------------------------------+
                             |
                     Direct Control
                             |
  +-------------------------------------------------------+
  |                       HARDWARE                        |
  |               (CPU, RAM, Disks, Network)              |
  +-------------------------------------------------------+
```

### Core Responsibilities of the Kernel:
1. **Process Management:** Allocates CPU time to running processes and handles multitasking.
2. **Memory Management:** Keeps track of physical RAM and allocates virtual memory spaces so programs don't overwrite each other.
3. **Device Drivers:** Acts as the bridge so software can talk to physical hardware (network cards, storage drives, keyboards).
4. **System Calls:** Provides a secure API (`open()`, `read()`, `write()`, `fork()`) allowing user programs to request hardware actions from the kernel.

## 2. 🖥️ The Terminal, Shell & The File Tree

### Terminal vs. Shell
- **The Terminal:** The window on screen that takes keyboard input and displays text output.
- **The Shell (e.g., `bash`):** The program running inside the terminal that parses the commands I type, finds the corresponding programs, and asks the kernel to run them.

### "Everything is a File" & The Root Directory (`/`)
In Linux, almost everything is treated as a file or stream of data. Unlike Windows with drive letters (`C:\`, `D:\`), Linux uses a single hierarchical directory tree starting at root (`/`):

- `/` — The root directory where everything starts.
- `/bin` & `/usr/bin` — Where common user commands live (`ls`, `cat`, `mkdir`).
- `/etc` — Where system and software configuration files are stored.
- `/var/log` — Where system and service log files live (crucial for troubleshooting).
- `/home` — Personal home directories for regular users.
- `/proc` — A virtual filesystem generated by the kernel in memory that exposes system and hardware info.

## 3. 🛠️ Popular Linux Commands I Explored

Today I studied the most popular, day-to-day commands categorized by what they do:

### System & Identity Information
- `whoami` — Prints the current logged-in username.
- `hostname` — Displays the system's network name.
- `uname -r` — Displays the currently running Linux kernel version.
- `uname -a` — Prints all system details (kernel version, architecture, OS name).

### Navigating the Filesystem
- `pwd` — **P**rint **W**orking **D**irectory (where am I right now?).
- `ls` — List directory contents:
  - `ls -l` — Detailed long view (shows permissions, owners, file size, timestamp).
  - `ls -a` — Shows hidden files (files starting with a dot, like `.bashrc`).
  - `ls -lh` — Formats file sizes in human-readable units (K, M, G).
- `cd` — Change directory:
  - `cd ~` or `cd` — Return to home directory.
  - `cd ..` — Go up one level to parent directory.
  - `cd -` — Jump back to the previous directory.

### Basic File & Folder Operations
- `mkdir <folder>` — Create a new folder (`mkdir -p` to create nested folders without error).
- `touch <filename>` — Create an empty file or update timestamps.
- `cp <source> <dest>` — Copy files (`cp -r` to copy folders recursively).
- `mv <source> <dest>` — Move or rename files and folders.
- `rm <filename>` — Delete files (`rm -r` for directories).
- `rmdir <folder>` — Safely remove an empty directory.

### Viewing Content
- `cat <file>` — Display full file contents in terminal.
- `less <file>` — Scroll through larger files without crowding the terminal.
- `head -n 5 <file>` — Read the first 5 lines of a file.
- `tail -n 5 <file>` — Read the last 5 lines of a file.
- `tail -f <file>` — Continuously watch new lines added to a file in real-time (standard tool for logs).

## 4. 🔍 How Troubleshooting Works in Linux (The Theory)

One of the biggest takeaways from today's theory was understanding **how to approach problems and errors in Linux** like an engineer instead of panicking.

### 1. Exit Codes: `0` vs Non-Zero
Every command in Linux returns a numerical exit status code when it finishes:
- `0` means **Success**.
- Anything between `1` and `255` means **an error occurred**.

I can check the exit status of the previous command using:
```bash
echo $?
```
This is how automated scripts and CI/CD pipelines detect if a step succeeded or failed.

### 2. Standard Output (`stdout`) vs Standard Error (`stderr`)
Linux separates normal output from error messages:
- `stdout` (File descriptor `1`): Normal data generated by the program.
- `stderr` (File descriptor `2`): Error and diagnostic messages.

This separation allows developers to direct output to one file and error logs to another (e.g., `command > output.log 2> error.log`).

### 3. Where Errors & Logs Live
When something goes wrong on a Linux system or server, the answers are almost always in log files:
- `/var/log/syslog` (or `/var/log/messages`) — General system activity and OS events.
- `/var/log/auth.log` — Authentication attempts and sudo logins.
- `dmesg` — Kernel ring buffer messages (hardware faults, driver issues).
- `journalctl` — Queries logs managed by systemd.

### 4. How to Ask the System for Help
Before searching online, Linux has built-in documentation for almost every command:
- `man <command>` — Opens the official manual page with full explanations and flags.
- `<command> --help` — Quick summary of options and usage syntax.
- `which <command>` — Shows the exact binary path being executed.

## 5. 💻 Hands-on Practice: Trying Out the Basics

Since today was focused on theory, my hands-on practice was simple and focused—running essential commands to verify the concepts:

### 1. Checking My System & Kernel Details
```bash
whoami
# Output: hrishav

uname -r
# Output: 6.8.0-45-generic (my running Linux kernel release)

uname -a
# Prints full kernel and system architecture details
```

### 2. Basic Navigation & Directory Creation
```bash
# Verify current location
pwd

# Create a simple test folder for today's notes
mkdir day02-practice
cd day02-practice

# Confirm I moved into the directory
pwd
```

### 3. Creating & Reading a Simple File
```bash
# Create an empty file
touch notes.txt

# Write some text into it
echo "Day 02: Exploring Linux Kernel and Commands" > notes.txt

# Read the file content
cat notes.txt
# Output: Day 02: Exploring Linux Kernel and Commands
```

### 4. Testing an Error & Checking Exit Code
```bash
# Attempt to view a file that does not exist
cat nonexistent.txt
# Output: cat: nonexistent.txt: No such file or directory

# Inspect the exit code of the failed command
echo $?
# Output: 1 (indicates failure)
```

### 5. Cleaning Up
```bash
# Go back to parent directory
cd ..

# Remove the test folder and its content
rm -rf day02-practice
```

## 📌 Key Takeaways from Day 02

1. **Linux is the Kernel:** It manages CPU, memory, and hardware; the distribution adds the shell and tools.
2. **Everything has a Path:** Absolute paths start at `/`, relative paths start from `pwd`.
3. **Troubleshooting is systematic:** Check error messages, verify exit codes with `echo $?`, and inspect logs in `/var/log/`.
4. **Built-in help exists:** Use `man` and `--help` to understand any command without guessing.
